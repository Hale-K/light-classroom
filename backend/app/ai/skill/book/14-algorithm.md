# 排课算法与流程

何时：算法、怎么排的、求解器、排课原理、流程分析、为什么这个方案、卡在哪一步、日志怎么看。

生成是五阶段后台管线（诊断抽屉展示同一管线）：校验任教与课时 → 白天课求解（OR-Tools CP-SAT）→ 晚自习求解 → 硬规则验算 → 写入课表。失败会停在卡住的阶段并给出原因。

口径：
- 硬约束（禁排、限排、教师冲突、课时结构等）必须全部满足才写入；软约束（均衡分布、班级紧凑、跨日分散、偏好工作日）只影响打分，不满足不阻塞。
- 求解失败分两类：INFEASIBLE（数学无解，与随机种子无关，按 13-diagnose 容量验算）与 超时未出候选（放宽约束、减少课时或加时）。
- 每轮单解最长 900 秒，默认最多 3 个求解候选（不同随机种子）；排出后还要过保存前硬规则验算，不过不写入。
- 白天课与晚自习分开求解；晚自习由晚课科目与单双周配对驱动。

分析流程时的取数顺序：先 lookup_generation_status 看状态，再 lookup_generation_log 取求解事件原文（阶段/进度/消息），按阶段对照上面的管线找卡点；规则与容量数字用 lookup_rules、lookup_subject_capacity、lookup_slot_role_capacity、lookup_remaining_capacity。数字全部来自工具，不要臆测算法内部参数。

不要：把软约束当成硬约束解释失败；不要说"算法有 bug"，除非用户给出与数据矛盾的具体输出；不要报源码路径。
