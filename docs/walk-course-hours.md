# 走班课时数据结构

## 走班配置入口与存储

基础课位按学校、年级、学年、学期独立保存。`scheduling_grid_plan` 保存范围和首周周次；`scheduling_grid_day` 保存每天正式课与单、双周晚自习数量；`scheduling_grid_slot` 保存逐格周次覆盖；`scheduling_grid_subject` 保存晚自习学科范围。迁移只为尚无年级方案的范围复制原学期配置，不覆盖已设置的年级方案。

基础课位使用滑块生成可视化矩阵，点击格子可设置每周、仅单周、仅双周或停用，再统一保存。晚自习接在正式课每日上限之后。CP-SAT 分别读取单周和双周可用课位，每周课程必须位于两周均可用的课位；写入前再次检查课位，失败时不覆盖课表。

入口为“排课管理 → 课位结构 → 走班配置”，与“基础课位”并列为子页签。旧的 `tab=walk` 链接兼容跳转到 `tab=slots&slotMode=walk`。

`walk_scheduling_plan` 按学校、年级、学年、学期唯一保存方案及修订号；`walk_scheduling_slot` 保存允许走班的星期与节次；`walk_scheduling_room` 保存共享教室范围。草稿可以不完整，保存时检查课位和资源归属，并用修订号避免覆盖他人的修改。

本阶段只支持每周白天课位。页面只维护允许走班的时段和共享教室范围；尚未接入行政课与走班课联合求解，也不会调整已有课表。

“计算推荐时段”是只读预览：先核对每名学生的确认选科与教学班名单，再按各班实际周课时求解。学生、教师不能同时上两门课；每班每天最多两节；各时段的教室数量和容量必须足够，并避开已有行政课和其他年级走班课占用。优先减少年级共享时段数，再分散到各教学日。未指定教室时使用当前范围全部可用共享教室计算，但不自动勾选；点击“使用推荐选择”只更新草稿。显示的推荐窗口数不等于每名学生的周课时。尚无行政课表时必须明确提示未做未来行政课实际时间校验；预览不等于正式联合排课成功。

科目课时方案是独立业务数据，不存入系统配置 JSON，也不借用行政班课时记录。

## 表与关系

`teaching_subject_hour_plan` 保存年级某学期某科目的默认周课时。字段包括 `id`、`tenant_id`、`grade_id`、`subject_id`、`academic_year`、`term`、`weekly_periods` 和创建/更新时间。

- 唯一键：学校 + 年级 + 学年 + 学期 + 科目。
- 学期只能为 `1` 或 `2`，周课时为 1–12 的整数。
- 年级、科目使用外键，删除有关基础数据时受限制。

`teachingclass` 保存教学班的实际 `weekly_periods`，新增 `hour_plan_id` 外键指向来源方案，以及 `hours_overridden` 标识单班调整。历史班级允许没有来源方案，保留原实际课时。

科目方案与教学班是一对多关系：方案可以先于教学班存在，教学班是方案在实际组班时的课时快照。学生成员、教师、教室和排课结果继续属于教学班，不属于科目课时方案。

## 生命周期

1. 可以在尚未组班时配置科目课时。
2. 生成教学班时继承当前学校、年级、学年、学期的科目方案。生成请求显式指定的科目课时优先，存在差异时记录调整标识；没有方案时沿用生成请求的课时参数，预览会提示使用的默认值。
3. 按科目保存课时会同步本范围内该科所有教学班，并重置单班调整标识。界面明确提示这个行为。
4. 单班调整只改变该班实际课时，不改变科目默认方案。
5. 实际课时变化时，仅清除有关教学班的走班排课结果，要求重新排课；不修改其他学期或学校的数据。
6. 重新生成教学班必须先预览，并明确确认替换本范围旧教学班。新班继承科目方案；旧班成员、教师教室安排、走班排课及单班调整不自动迁移。

## 数据库部署

DDL：`db/schema/teaching_subject_hour_plan.sql`；Alembic 版本：`v2e4f6a8b0c1`。DDL 可重复执行，仅创建新表及增加教学班来源字段，不为历史记录推断默认科目课时。

## 页面入口与范围

排课管理 → 课时管理 → 走班课时，以年级和科目维护默认课时，展开科目可单独调整教学班。本次覆盖课时方案及组班继承；走班的教师、教室与排课流程没有在本次重新设计。

## 教学班生成与共享教室（2026-10-06 更新）

- `POST /gaokao/teaching-classes/generate` 传 `preview=true` 返回各班人数、周课时、已有班数、可用共享教室数、提醒及 `preview_token`，不写业务数据。
- 确认生成携带该令牌；选科、班额、课时或已有班级状态变化后令牌失效，必须重新预览。已有教学班还须传 `replace_existing=true`。
- 每科按 `ceil(人数/班额上限)` 确定班数，再均衡分配，每班人数最多相差 1 人。人数上限在页面可编辑。
- 组班不依赖教室是否配置；教室容量问题作为预览提醒，排课时再严格校验。
- 共享池以 `RoomCohortAllocation` 和有效的 `ResourceAllocationRule` 为唯一来源，限定学校、学年、学期、届别、校区、可排课状态；旧的 `TenantConfig` 年度教室池不再读取，旧写入接口返回 410。
- `POST /gaokao/schedules/generate` 支持 `room_ids` 子集，只能选本范围可用共享池中的教室。页面不默认勾选，可只选部分。未传该字段时保留服务端使用可用池的行为，班数不等于教室数。
- 预览及组班不会修改行政班课时或行政班名单。高一下的阶段设置仍只允许预编教学班，正式走班排课的既有阶段限制保持不变。
# 教学班任教关系

排课管理的“任教关系”提供行政班任教、教学班任教两种视图；教学班结果中的“安排教师”跳转到教学班视图并带入年级。

教学班视图读取当前学校、年级、学年、学期的实际班级，支持同科目批量安排、单班安排、更换及解除。教师选项由有效学科组成员关系确定，只采用无学年限制或匹配所选学年的组织任命。教师行政任教周课时取该学期 TeachingAssignment 配置，走班课时取该学期各年级 TeachingClass 配置；这里展示配置课量，不代表已经排入课表的节数。

新增 GET `/gaokao/teaching-classes/teachers` 和 PATCH `/gaokao/teaching-classes/teachers`，均要求管理权限。批量写入先验证全部班级和教师，按年级锁串行处理。请求需携带原教师 ID；原关系已变化返回 409，相同教师重复提交返回 updated=0。已存在走班课表的班级不能直接变更或解除教师，必须先处理课表调整。此次没有新增重复任教表，教学班教师继续保存于 TeachingClass.teacher_id。
