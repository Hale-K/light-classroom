# 排课业务与助手交互

## 业务依据

| 环节 | 真正的数据/代码依据 | 助手应该做什么 |
|---|---|---|
| 确定范围 | 当前学年学期，Grade/Class，页面选中的年级与规则组 | 明确本轮对象；不默认高一、不把全校统计当某年级统计 |
| 课位 | scheduling._load_grid_config，daily_periods 及晚课单双周配置 | 判断已保存的实际每天容量；不能只用天数乘最大节数 |
| 课时 | CourseHourPlan，_apply_course_hour_plans | 科目课量以课时方案为准，分工作日/周六/晚课/单双周；旧任教课量只作兼容 |
| 任教 | TeachingAssignment，_generation_assignment_payloads | 匹配班级+科目；存在若干任教记录不能证明全部课时都有老师 |
| 规则 | RuleGroupDocument，compile_rule_group，_resolve_generation_rule_group | 先明确组与年级；草稿校验不代表整体可行；不默默切启用组 |
| 生成前检查 | validate_schedule / _validate_generation | 检查容量、教师负荷及选科冲突，不能把数量概览包装成已通过校验 |
| 生成 | generate-jobs，generate_jobs，Celery daytime/evening solver | 后台长任务；状态包括等待、校验、求解、刷新和终态，不承诺固定耗时 |
| 验收 | verify-schedule，diagnosis，weekly/calendar | 生成完成与无冲突是不同结论；确认未排课量和硬约束诊断 |
| 调整与恢复 | adjustments/preview，adjustments，versions/restore | 先预览影响再操作，保持版本与审计边界 |

## 本次实现

1. 助手对话改为持久任务：先返回编号，轮询阶段和心跳，支持取消和刷新恢复；保留旧聊天接口。
2. 进度来自模型请求、实际查询和草稿处理回调；心跳仅表示服务仍在响应，不伪造步骤或百分比。
3. 区分等待模型、阶段耗时、网络暂时不可达、任务超时、服务中断和完成。老师可关闭面板继续工作。
4. 把上述流程写入模型常驻规则，并增强准备度查询，明确缺项与尚未验证的部分。

验收：慢模型有持续心跳；取消/超时终止底层请求；刷新能恢复同一任务；网络恢复不重复提交；终态后停止轮询；新对话不接收上一轮结果；身份隔离；不调用工具就不声称已查询。

## 验证结果与边界

38 项后端检查通过，含任务编号幂等、账号隔离、中断标记、超时取消、阶段回调及 PostgreSQL 完成/取消竞争。前端构建与浏览器交互验证通过；浏览器验证刷新不会新建任务、停止等待后台确认、草稿确认冲突反馈和移动端无溢出。

任务状态持久化，执行仍在 API 进程中；重启会报告中断，不自动重放。刷新恢复目前针对同标签页助手任务，不代表课表生成器自动恢复或完整历史对话持久化。助手仍不直接生成课表或调课。求解器原有一项 4+2 课量分配回归失败未在本轮修改。
