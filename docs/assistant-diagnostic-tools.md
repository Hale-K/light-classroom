# 助手排课排查工具

工具用于读取事实，不用来枚举用户问法。模型根据工具说明选择查询，服务端执行只读 SQL 或读取任务状态；不能改教师、分班、规则或课表。普通查询和诊断工具权限已补齐，规则写入仍单独确认。

| 工具 | 可获得的证据 | 不可据此声称 |
| --- | --- | --- |
| lookup_generation_status | 当前已知生成任务真实状态、最近进展 | 无进展就是正常运行，或所有课已排完 |
| lookup_generation_log | 已有任务最近40条求解事件原文 | 日志没记录的根因；缺任务编号时自动重跑 |
| lookup_schedule_setup | 班级课时、课位和任教覆盖 | 准备完整就一定有解 |
| lookup_rules | 当前启用硬约束和软目标 | 自动删除或放宽规则 |
| lookup_subject_capacity | 科目课时、限排课位、教师并行容量 | 容量足够就能满足所有组合约束 |
| lookup_remaining_capacity | 已配置课时与课位容量差值 | 所有空课位都能容纳指定课 |
| lookup_slot_role_capacity | 指定教师角色授课的必要条件 | 完整联合求解可行性 |
| lookup_walk_classes | 保存的教学班数、班额、入班人数、固定教师、配置课时、已排节数、教师不一致；同科教师人数统计 | 未保存预览、行政加走班总工作量、未经求解的唯一根因 |

新增走班工具必须明确年级，可用页面年级或用户确认的名称/ID。显式年级名称覆盖页面年级；歧义或跨学校ID返回需澄清，不自动查全校。输出不含学生姓名和名单。教师配置课时与已排课节分开，人次与去重人数分开；空壳教学班没有学生不能直接判错。

聊天入口不再因准备或诊断标签自动运行固定三组检查，而是进入有权限和预算边界的 Agent 工具循环：模型根据问题及每次工具返回决定回答、追问或继续查询。分类器的单个工具提示不锁死后续只读查询。标准 Supervisor 模块保留，但不再是普通聊天的默认入口，也未新增标准检查按钮。

目前普通循环最多三次模型调用，末次只输出答案；工具结果长度限制和更完善的停止策略是下一步，不应宣称复杂问题已能完整诊断。逐条学生/教师/教室冲突定位、预览对比和求解器不可满足约束集合仍需后续补齐。

应答要求：先给有证据的事实，再标明推断；查不到时说明缺什么，不声称检查通过。用户只问某科或某老师时，不扩成全校任务。脱敏历史问题适合先制作独立评测集，按不同问法检验工具选择、澄清和答案依据，不自动写入训练库。
