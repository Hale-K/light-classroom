# 轻课堂易用性与业务完整度改进计划

## 目标

让校长、教务老师和一线教师能围绕真实工作任务完成操作，不必先理解排课算法、规则模型或系统内部术语。每个主要流程都要说明当前进度、下一步入口、操作影响和失败后的修复办法。

## 当前证据与基线

- 排课页面已有课时、课位、任教、规则和课表多个页签；用户需要自行组织准备顺序。
- `docs/scheduling-preparation-flow.md` 已定义从学期、教师、场室、班级到排课准备的十步流程，并说明“有基础记录”不代表通过完整校验。
- 轻高考走班联合预览已有学生完整课表、行政班课表、教学班课表、分班结果，以及年级、行政班、学生查询；选科方向和完整组合可见。
- 代码库中已有排课诊断、生成进度、助手和规则工作台等能力，后续应把反馈放回用户当前任务中，避免让用户在多个工具间猜测。

## 阶段一：让排课主流程可自助完成

### 任务 1：在排课页显示准备清单

把现有准备检查呈现在排课主页面。按当前年级、学期和排课模式展示已完成项、待处理项和明确入口；检查结果不充分时标记“待检查”，不误报为已完成。

验收：

- 用户进入排课页即可看到从准备到查看课表的顺序及当前进度。
- 每个未完成项有对应的页面入口，点击后保留年级和学期上下文。
- 准备状态区分“缺少基础数据”“尚未校验”和“已通过校验”。

### 任务 2：把排课校验结果变成可执行的修复建议

统一展示课时不足、开放课位不足、教师未分配或超负荷、教室冲突及规则冲突。每条反馈指出对象、当前值、要求值和可前往的设置位置；可自动修复的项目由系统给出建议，并说明影响范围。

验收：

- 不向普通用户只展示求解器状态、内部 ID 或原始 JSON。
- 每项失败信息能对应到班级、学科、老师或具体时段。
- 用户修复后能从原流程重新校验，不必重复无关步骤。

### 任务 3：收敛联合预览与保存反馈

保持联合排课一次性预览行政课和走班课；在保存前说明替换范围、保留内容和覆盖内容。保存成功后显示生成数量、查询入口和后续操作。

验收：

- 用户能分年级、行政班、学生查看联合预览，并读懂选科方向与组合。
- 切换预览范围后旧结果失效，未重新预览时无法保存。
- 保存前能看见明确影响范围；保存后能直接打开对应年级课表。

## 检查点：排课闭环

- 从尚未准备完成的状态开始，按页面提示完成准备、预览、修复、保存和查询。
- 普通用户不需要手动建立求解器规则才能完成常见排课。
- 对预览失败、数据缺漏和保存后查询，均有清晰且一致的页面反馈。

## 阶段二：让常用教务任务更省力

1. 梳理学生档案、选科确认、任课关系、教师档案和空间资源的入口及依赖，清理重复配置。
2. 优先支持批量操作、模板导入和保存默认值；重要字段提供示例和即时校验。
3. 为每个模块补齐空状态、加载状态、失败重试和成功后的下一步入口。
4. 对跨学期操作显式显示当前学年、学期和年级，并在页面切换时保持上下文。

验收以常见校务任务完成情况为准：新建学期、准备学生与选科、配置任课与资源、完成排课、查询并导出结果。

## 阶段三：按角色补齐产品闭环

以校长/管理员、教务人员、教师和学生的日常目标检查菜单、权限和任务入口。只显示与角色当前工作相关的主要动作；保留高级配置，但降低默认界面的干扰。检查排考、班级排座、成绩/考试与文件中心是否能从准备、执行到结果查看完整闭环。

验收：

- 各角色能从工作台找到最常用任务。
- 权限限制有清楚说明，不以不可解释的禁用按钮结束流程。
- 各主要业务能说明所需数据、完成状态、结果位置及失败后的下一步。

## 实施原则

- 每次交付一个完整的用户任务切片，避免只改视觉或只加后端能力。
- 先核对现有业务规则和数据来源，再设计文案与交互；不以猜测补造业务状态。
- 预览和校验不应覆盖正式课表；任何覆盖操作都在确认前明确展示范围。
- 每个改动用真实页面操作验证，并根据影响范围选择对应的自动化检查。
- 保留现有用户修改；小步交付并记录尚未覆盖的场景。

## 优先顺序

1. 排课页面整合准备状态与下一步入口。
2. 排课失败信息及可执行修复路径。
3. 联合预览保存前后的范围说明与查询闭环。
4. 学生/教师/资源等数据准备流程的批量能力和跨页上下文。
5. 按角色梳理其他教务模块及端到端验收。
