# 多教学场景改造规格与实施计划

日期：2026-10-19。状态：**已按用户要求整体回滚（2026-10-19），代码与开发库均恢复到改造前状态**。本文件保留作为方案记录；如重启此项工作，§1–§8 的方案与阻塞点分析仍然有效，§9 的实施记录可作参考，但需重新评估。

## 1. 目标与范围

用户确认先完成教学配置与排课全链路：学校类型、学制年级、行政班和教学班、课程课时、任课、选课、规则、Excel、Agent、网页端和离线客户端。大学学位毕业审核、成绩绩点体系、教培收费退费、考勤课消和财务结算不在本轮。

支持小学、初中、高中、教培、大学、多学段混合学校；通过可配置学制、日历和授课组织支持职教、成人教育等扩展场景。这里的“支持”必须通过各场景端到端验收，不能仅增加一个学校类型下拉框，也不承诺穷尽所有教学制度。

默认设计假设：

- 一所学校是一个租户，可以同时包含多个学段或培养项目。
- 小学初中可有多种学制；大学可有多个不同学制的专业；培训项目允许没有年级、不自动升学。
- 机构类型、学段、授课组织、高考选科制度彼此独立；高中保留 3+1+2、3+3、传统文理。
- 同一机构、同一教学周期内，行政班授课、选课走班、跨班合班、一对一可并存。
- 老师和房间可在本校多个项目间共享，跨项目资源冲突必须统一计算。
- 现有高中学校保持原配置和历史课表；用户明确选择后才启用新的教学配置。

## 3. 目标模型

### 3.1 学校配置与培养项目

保留 Tenant 的租户标识和现有账号体系。新增独立教学配置，不复用 Tenant.type（原组织类型）或 gaokao_mode 表示机构类型。

建立 EducationProgram：归属租户、名称、学段、是否按年级组织、学制、允许的教学组织方式、科目/课程预设、校历引用、可选高考方案。一个租户可有多个项目。预设只是创建向导的起点，修改预设不能重写学校已保存配置。

Grade 归属明确项目；同名“一年级”可属于不同项目。年级顺序与名称分开，升级使用显式下一年级关系；跨小学到初中等学段迁移必须预览确认，不能只因 level 相邻自动跳转。无年级培训不能创建“虚拟高一”凑旧接口。

默认预设：

| 类型 | 创建向导预设 | 允许调整 |
|---|---|---|
| 小学 | 六年、行政班、白天授课 | 五年学制、兴趣选修、合班、不同作息 |
| 初中 | 三年、行政班 | 四年学制、分层/选修、跨班课程 |
| 高中 | 三年、行政班，可启用高考选科 | 3+1+2/3+3/传统文理、行政与走班混合 |
| 大学 | 项目/专业、课程目录、开课班、选课 | 不同学制、学分信息、多教师、跨专业选课、周次范围 |
| 教培 | 项目/课程、开班批次、小班或一对一 | 无年级、周末/晚间、固定日期、不同课长、合班 |
| 混合/自定义 | 显式选择多个项目及其能力 | 不强制使用某个学段的默认制度 |

### 3.2 校历和教学周期

AcademicPeriod 保存周期编号、显示名、起止日期、归属项目/校历；支持春秋学期、第三学期、短学期、暑期和培训批次。新接口使用 period_id；旧 academic_year/term 通过映射访问同一数据。

Calendar 保存时区、周起点、有效教学日期、周次编号、休息日、调休补课日、每日时段的开始/结束时间。单双周是周次集合的快捷选项，不是新的日期真相。明确课程的授课分钟数与“课时”换算单位，不能把所有课时默认为 45 分钟。

允许不同项目使用不同作息。教师/学生/房间冲突按具体日期和时间区间判断，而非只比较“第几节”。可配置校区间移动缓冲。

### 3.3 课程目录、开课班和任课

区分三个对象：课程目录（教什么）、开课班 CourseOffering（哪个周期、哪些学生上）、授课任务（由谁、在哪、何时、上多久）。保留现有 Subject 作为课程目录兼容入口，扩充编号、名称长度、类型和可选学分。学分仅为教学配置属性，不实现毕业审核。

新教学组织统一覆盖行政班课程、选课教学班、跨班合班、分组实践和一对一。沿用现有 Class、TeachingClass、成员关系的业务 ID；通过明确关联映射接入开课班，不直接删表改名。

开课班可以关联一个或多个原行政班，或关联独立学生名单；无行政班学员也能参加。任课支持主讲/协同教师，多教师授课必须区分“同时到场”与“分别承担不同课次”。同一课程本期可有多个开课班和不同课时，不能覆盖成一行任课。

选课使用学生与开课班的关系，支持容量、开放/截止时间、退选、重复报名检查、已发布课表冲突检查。高中选科组合仍使用原策略验证，再映射到开课班；普通选课不能被要求选“物理或历史”。本轮不扩展抢课排队、支付、毕业学分审查。

### 3.4 统一排课输入与历史兼容

逐步为现有行政班和走班排课器增加同一个标准化输入层，保留已经验证的约束和求解组件；不维护几套按学段复制的排课算法。

标准输入最少包括：租户、周期、配置修订号、开课班、教师集合、学生/班组集合、房间候选、授课次数和时长、有效日期/周次、允许时段、资源不可用区间、硬约束与偏好。

必须覆盖：

- 教师、学生、行政班/教学组、教室冲突；共享资源跨项目冲突。
- 容量、教室类型、校区及移动时间；固定课次、多教师、合班。
- 工作日/周末/指定日期、单双周/周次范围、连续时段、日负荷与间隔。
- 周期课程和指定日期课程在同一天的冲突；假期/调休日不凭名称推断。
- 手动调课和自动生成使用同一校验器；不可满足时报告实际冲突对象和规则，不能静默放松硬约束。

输出使用具体课次及配置快照；兼容层向旧周课表界面提供视图。每个迁移阶段只指定一个写入源，通过同一事务映射旧字段，避免两套课表长期双写后漂移。历史已发布版本只读解释，不被学校当前配置追溯修改。

### 3.5 UI、Excel 和 Agent

- 平台创建学校：选择类型/项目预设，非高中不要求高考模式。
- 学校设置：项目、学制、年级、校历、教学周期、能力；切换预设展示影响，不自动修改已有业务数据。
- 工作台和菜单按能力展示；保留权限控制，隐藏菜单不能替代服务端校验。
- 班级/开课页面可区分行政归属与实际授课名单；课表支持班级、教师、学生、教室、项目及日期视角。
- Excel 新模板包含项目/年级、课程、开课班、课时/课次、任课、选课名单、规则等可选工作表；旧模板走明确的兼容导入。
- Excel 预览必须显示真实学校、项目、周期、数据来源和新增/复用/冲突项。未知表头、同名多匹配、周次/课时歧义阻止执行并请求澄清，不自动补造师生或班级。
- Agent 的工具按学校能力提供，读取本校实体解析年级和课程；不把问教室数量误解成查课表，不把无生成任务误报为无课表。
- Agent/Computer-use 延续“只读解析 → 预览 → 用户二次确认 → 执行”；停止接管阻止后续写入，已经完成的写入有日志与恢复记录。

## 4. 数据兼容与发布策略

1. 先对测试库进行清点：高中模式、行政/教学班、课程、旧学期标识、已发布课表、规则、冲突数据。
2. 使用版本化迁移，先新增表/可空关联，再批次回填、核对、补约束。SQLite 和 PostgreSQL 都要执行相应迁移测试。
3. 现有学校的初始教学类型按原产品契约兼容为高中，保留其高考模式；不能从学校名称猜测其他类型。历史数据无法唯一归属项目或日历时输出待确认清单。
4. Grade 原 `(tenant_id, name)` 唯一约束需迁为项目作用域；旧 term=1/2 的 CheckConstraint 必须显式迁移。SQLite 涉及改约束时使用受控表重建和外键核对，不能只调用 create_all。
5. 保留旧 ID 与学年/学期映射；已建方案和已发布课表保留快照，迁移重复执行不得重复创建项目、周期或课程。
6. 改造过程先在隔离测试库验收，真实库升级前有备份、预览、校验报告和回退点。此需求授权修改项目代码，不自动授权清空或重写真实学校业务数据。
7. 桌面 SQLite 使用相同迁移契约；普通/离线/演示/联网模式及 7 天试用行为回归。旧 EXE 不会随源码改动自动更新。
8. 部署顺序兼容新旧前端：先兼容读取与迁移，再新 UI，最后启用新功能。跨版本回退不能删除新增业务数据。

## 6. 场景验收矩阵

每行均走完整链路：建校/项目 → 日历/周期 → 人员/学生/房间 → 课程 → 课时任课 → 导入/选课 → 规则 → 生成预览 → 发布 → 手动调整 → 导出 → Agent 查询。

| 场景 | 必测差异 |
|---|---|
| 六年小学 | 一至六年级；三升四；兴趣班与行政班共存；无高考/晚自习必填 |
| 五四学制 | 小学五年与初中四年互不混淆；毕业/升级目标正确 |
| 三年初中 | 无高考配置也能排课；体育/实验专用空间与普通教室限制 |
| 高中 | 三种高考模式、行政/走班混合、单双周晚课、旧课表与已建方案快照 |
| 大学 | 两个专业不同学制；第三/短学期；多个开课班；跨专业选课；1–8/9–16 周；多教师与不同课长 |
| 教培 | 无年级学员；一对一和小班；周日、晚上、指定日期；同一教师多个项目；不强制固定行政班 |
| 混合学校 | 小初高同名年级；共享教师/教室；不同作息时间重叠仍检出冲突 |
| 安全及失败 | 跨租户 ID、过期预览、重复确认、并发选课容量、矛盾硬规则、求解超时、批次中断、恢复重试 |

核心断言：课时守恒；硬冲突为零；学生/教师/场地冲突基于真实时间；规则作用域准确；预览不写库；确认后写入可追溯；任何不满足都明确报错；老高中数据不被重新解释丢失。
