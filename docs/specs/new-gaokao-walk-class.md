# 新高考选科走班与排课规格

## 目标

在保留现有行政班排课的前提下，新增可配置的新高考方案、学生选科、教学班自动编排和走班课表。第一阶段默认使用“3+1+2”：语数外为必考科目，物理/历史二选一，化学/生物/政治/地理四选二。

业务顺序固定为：开通学生账号 -> 学生登录并提交选科 -> 班主任审核 -> 汇总已审核选科人数 -> 校验师资和教室资源 -> 根据班额生成教学班 -> 将学生加入对应的教学班 -> 为教学班排课。系统不得在学生选科前预设限定组合教学班。

## 已确认假设

- 默认方案为“3+1+2”，省份、入学年份和方案名称可配置。
- 行政班继续承担学生日常管理；教学班按学科和选科结果生成，两者并存。
- 学生每个生效学期只能有一份确认选科，保留轮次与状态字段供后续变更流程使用。
- 自动分班以班额为硬约束，第一阶段同一学科内按名册顺序确定性分组。
- 走班排课的硬约束包括教师、教学班和教学班成员在同一时段不得冲突。
- 教学班生成前必须存在对应学科的有效任教关系和足够容量的可排课普通教室；资源校验失败时保留原有教学班结果。
- 走班排课同时校验教师、教学班、学生和教室在同一时段不得冲突。
- 学校系统设置中的默认高考模式会在学生端首次读取时自动初始化为可用的选科方案，避免只配置模式却没有方案记录。
- 算法无法完整排入时返回未排任务，不静默违反硬约束。
- 现有 5500 名学生生成均衡但非完全平均的 12 种组合测试数据，不代表真实学校选科比例。

## 数据模型

- `GaokaoScheme`：学校、省份、模式、入学年份、必考/首选/再选科目配置、启用状态。
- `StudentSubjectChoice`：学生、方案、学年、轮次、首选科目、两个再选科目、状态、生效学期。
- `TeachingClass`：年级、学科、教师、教室、学年学期、班额、周课时、生成来源。
- `TeachingClassStudent`：教学班与学生多对多成员关系。
- `TeachingClassSchedule`：教学班课表项。
- `StudentCredential`：与教职工账号隔离的学生登录凭证，按学校和学号唯一。

## API 契约

- `GET /api/v1/gaokao/overview`：方案、选科覆盖率、组合分布、学科需求、教学班概览。
- `POST /api/v1/gaokao/schemes`：创建或更新当前学校方案。
- `PATCH /api/v1/gaokao/students/{student_id}/choice`：维护单个学生选科。
- `POST /api/v1/gaokao/teaching-classes/generate`：按选科人数和班额生成教学班及成员。
- `POST /api/v1/gaokao/schedules/generate`：生成走班课表。
- `GET /api/v1/gaokao/schedules`：查询教学班或学生课表。
- `POST /api/v1/student-auth/login`：学生使用学校代码、学号和密码登录。
- `POST /api/v1/student-auth/accounts/provision`：管理员按年级批量开通或重置学生账号。
- `GET /api/v1/student-auth/context`：获取学生端当前学年和学期。
- `GET /api/v1/student-auth/choice/options`：获取当前学校方案和学生可选科目。
- `GET /api/v1/student-auth/choice`：查询当前学生选科。
- `PUT /api/v1/student-auth/choice`：学生保存草稿或提交选科。
- `GET /api/v1/gaokao/choices`：查询待审核选科；班主任只看到自己担任班主任或副班主任的行政班。
- `PATCH /api/v1/gaokao/choices/{choice_id}/review`：班主任单条通过并锁定，或驳回后允许学生重新提交。
- `POST /api/v1/gaokao/choices/batch-approve`：批量通过并锁定已提交选科，单次最多 500 条。

接口继续使用现有 `{ code, message, data }` 响应结构，所有写入都校验租户和引用资源。

## UI

- 新增“新高考走班”工作台。
- 顶部展示选科覆盖率、12种组合数量、教学班数和未排冲突。
- 组合矩阵展示物理/历史方向与再选组合人数。
- 学科需求视图展示人数、预计教学班数、已配教师与师资负载。
- 教学班列表展示班额、教师、教室、周课时与排课状态。
- 支持配置班额、自定义周课时并生成教学班和走班课表。
- 学生档案页提供“批量生成学生”和“开通学生登录”两个独立工具：前者只生成测试档案，后者为已有学号的学生创建登录凭证。
- 教学班生成失败时，页面应展示具体缺失学科教师、教室数量或教室容量原因。

## 推荐操作流程

1. 在学校组织、年级和学生档案中准备当前届次数据；没有真实名单时，可用“批量生成学生”创建测试学生。
2. 在“学生档案”中按年级点击“开通学生登录”，设置初始密码，并将学校代码、学号和初始密码发给学生。
3. 学生访问 `/student/login`，登录后进入“我的高考选科”，先保存草稿，确认后提交选科。
4. 班主任登录教职工账号，在新高考走班工作台的“班级选科审核”中查看本班已提交学生；可以逐条审核，也可以勾选后批量“通过并锁定”。
5. 对不符合要求的选科选择“驳回”，学生会看到驳回状态并可以重新提交；通过后的选科会锁定，学生不能自行修改。
6. 教务人员在工作台检查已审核选科覆盖率和组合分布，确认每个走班学科已有任教关系。
7. 检查“空间资源”中的普通教室：必须启用、状态为可用，且容量不低于教学班班额。
8. 生成教学班。系统会先做资源校验，校验通过后才替换同年级同学年学期的旧教学班。
9. 生成走班课表。算法会避开教师、学生、教学班和教室的同一时段冲突；无法安排的课时会明确返回未排任务。

## 测试策略

- 单元测试：3+1+2选择合法性、教学班容量、成员覆盖、走班学生冲突、教师冲突、教室冲突。
- 数据验证：5500名学生均有唯一确认选科，教学班成员不超过班额。
- 构建验证：`python -m pytest -q`、`pnpm typecheck` 与 `pnpm build`。
- 浏览器验证：概览统计、组合矩阵、教学班生成和走班课表页面无控制台错误。

## 边界

- 本阶段不删除或替代传统行政班排课。
- 本阶段不接入高校专业选科要求外部数据源。
- 本阶段不接入学分认定和家长确认；选科审核由班主任完成，教务可查看全校审核汇总。
- 当前学生端已支持草稿/提交、驳回后重新提交和审核通过后的锁定状态校验。
- 本阶段不加入外部求解器；使用可测试的确定性算法并明确返回未排任务。

## 验收标准

- 5500名学生具备有效的“3+1+2”测试选科。
- 能按年级和班额生成教学班，所有教学班不超容量。
- 每名学生恰好加入其3门选考科目的教学班。
- 走班课表不存在教师、教学班或学生同时段冲突。
- 教务管理员可在页面查看组合分布、师资需求、教学班和课表结果。
- 学生可独立登录并提交自己的选科，不能读取或修改其他学生数据。
- 数据库迁移、核心后端测试、前端类型检查和生产构建通过；完整回归仍需同步更新旧菜单断言测试。
