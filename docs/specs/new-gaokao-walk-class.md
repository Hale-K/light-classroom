# 新高考选科走班与排课规格

## 目标

在保留现有行政班排课的前提下，新增可配置的新高考方案、学生选科、教学班自动编排和走班课表。第一阶段默认使用“3+1+2”：语数外为必考科目，物理/历史二选一，化学/生物/政治/地理四选二。

业务顺序固定为：学生提交选科 -> 汇总各科人数 -> 根据班额和师资生成教学班 -> 将学生加入对应的3个教学班 -> 为教学班排课。系统不得在学生选科前预设限定组合教学班。

## 已确认假设

- 默认方案为“3+1+2”，省份、入学年份和方案名称可配置。
- 行政班继续承担学生日常管理；教学班按学科和选科结果生成，两者并存。
- 学生每个生效学期只能有一份确认选科，保留轮次与状态字段供后续变更流程使用。
- 自动分班以班额为硬约束，第一阶段同一学科内按名册顺序确定性分组。
- 走班排课的硬约束包括教师、教学班和教学班成员在同一时段不得冲突。
- 算法无法完整排入时返回未排任务，不静默违反硬约束。
- 现有 5500 名学生生成均衡但非完全平均的 12 种组合测试数据，不代表真实学校选科比例。

## 数据模型

- `GaokaoScheme`：学校、省份、模式、入学年份、必考/首选/再选科目配置、启用状态。
- `StudentSubjectChoice`：学生、方案、学年、轮次、首选科目、两个再选科目、状态、生效学期。
- `TeachingClass`：年级、学科、教师、教室、学年学期、班额、周课时、生成来源。
- `TeachingClassStudent`：教学班与学生多对多成员关系。
- `TeachingClassSchedule`：教学班课表项。

## API 契约

- `GET /api/v1/gaokao/overview`：方案、选科覆盖率、组合分布、学科需求、教学班概览。
- `POST /api/v1/gaokao/schemes`：创建或更新当前学校方案。
- `PATCH /api/v1/gaokao/students/{student_id}/choice`：维护单个学生选科。
- `POST /api/v1/gaokao/teaching-classes/generate`：按选科人数和班额生成教学班及成员。
- `POST /api/v1/gaokao/schedules/generate`：生成走班课表。
- `GET /api/v1/gaokao/schedules`：查询教学班或学生课表。

接口继续使用现有 `{ code, message, data }` 响应结构，所有写入都校验租户和引用资源。

## UI

- 新增“新高考走班”工作台。
- 顶部展示选科覆盖率、12种组合数量、教学班数和未排冲突。
- 组合矩阵展示物理/历史方向与再选组合人数。
- 学科需求视图展示人数、预计教学班数、已配教师与师资负载。
- 教学班列表展示班额、教师、教室、周课时与排课状态。
- 支持配置班额、自定义周课时并生成教学班和走班课表。

## 测试策略

- 单元测试：3+1+2选择合法性、教学班容量、成员覆盖、走班学生冲突、教师冲突。
- 数据验证：5500名学生均有唯一确认选科，教学班成员不超过班额。
- 构建验证：`python -m pytest -q` 与 `pnpm --filter @zhiheng/web build`。
- 浏览器验证：概览统计、组合矩阵、教学班生成和走班课表页面无控制台错误。

## 边界

- 本阶段不删除或替代传统行政班排课。
- 本阶段不接入高校专业选科要求外部数据源。
- 本阶段不实现学分认定、选科审批流和家长确认。
- 本阶段不加入外部求解器；使用可测试的确定性算法并明确返回未排任务。

## 验收标准

- 5500名学生具备有效的“3+1+2”测试选科。
- 能按年级和班额生成教学班，所有教学班不超容量。
- 每名学生恰好加入其3门选考科目的教学班。
- 走班课表不存在教师、教学班或学生同时段冲突。
- 教务管理员可在页面查看组合分布、师资需求、教学班和课表结果。
- 数据库迁移、后端测试、前端构建和浏览器验收全部通过。
