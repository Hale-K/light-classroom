# 排课规则职责与冲突审查

审查日期：2026-10-09。范围：规则工作台、规则规范化、配置关系检查和行政课生成中的学科允许课位提取。这里的配置检查不能替代完整排课求解。

## 规则应该围绕老师的五个问题组织

普通规则只需选择**作用对象及名称、时间或课位、满足程度**。规则确实需要时，再显示次数、例外或单双周等字段；不额外添加“安排方式”这样的抽象选择。

一条规则判断的是某个要求，界面分类帮助找到要求；每天最多几节、只能在哪上、空档连续等不同要求仍各自有明确含义。硬性/尽量满足是每条规则的满足程度，不是额外规则。

| 老师要表达的要求 | 负责的位置 | 与其他要求的边界 |
| --- | --- | --- |
| 这门课/这位老师能在哪上，或哪些时间不上 | 时间与课位 | 允许与禁排方向相反；对象可选学科、教师、班级或全年级 |
| 科目每天上几次、连堂几节 | 学科每日次数 / 学科连堂 | 属于科目周课时的日分布；不能和教师每日负荷混为一谈 |
| 老师每天/每周工作量多少 | 教师负荷 | 每日上限、周课时下限各自明确；任课课时从任教关系计算 |
| 一天的课要不要连续、班级或学生能否有空档 | 连续与空档 | 教师、单个班级和学生跨班课表统计范围不同 |
| 一个课位单周/双周由不同科目轮换，或课程如何搭配 | 周次与协同 | 需要明确成对对象、周期课时或触发条件 |
| 每门课每周几节、单双周课时 | 课时管理 | 允许课位、连堂不负责增加课时 |
| 谁教哪个班的哪门课 | 任教关系 | 规则只能约束已有任教安排 |
| 学校一天有几节、哪些时段开课 | 课位结构 | 不要用一堆全局禁排代替停用课位 |
| 某对象某时间不上课 | 课位禁排 / 教师具体课位禁排 | 相同教师和课位表达的是同一职责；教师入口还能逐日设置不规则禁排 |
| 学科在哪些时间上，或优先排在哪里 | 学科上课时段（单一入口） | 同一组对象和节次；“必须满足”限定可排课位，“尽量满足”表达偏好并可设例外数 |
| 每天最多上几节 | 教师每天最多上几节 | 控制教师负荷，不自动要求连堂或中间无空节 |
| 教师授课中间不空节 | 教师每日上限中的独立可选要求 | 勾选后另写连续性约束；旧已开启配置保留，新规则默认关闭 |
| 学科/教师每周至少几天连堂 | 学科连堂 / 教师连堂 | 不等于全天无空节，也不等于每班所有课位排满 |
| 班级前七节有课 / 顺序连续 | 班级无空堂 | “前七节填满”和“连续、末尾可空”是不同模式 |
| 学生公共课与走班课衔接 | 学生连续 / 减少空档 | 对象是学生合并课表，不应被班级无空堂替代 |
| 晚课日期、相邻班晚课、白晚联动 | 教师晚课规则 | 晚课日期偏好明确标注只作用于晚课 |
| 班主任指定时间授课 | 课位教师角色 | 依赖班主任资料和对应任教关系，不指定具体学科课时 |
| 同一课位单双周轮换 | 白天/晚课单双周对课 | 依赖各科周期课时，不能替代课时配置 |

## 学科偏好的配置

“学科只能安排在某些时间”“主科尽量靠前”和“活动课优先后段”统一从“学科上课时段”进入。老师选科目和节次，再用满足程度决定严格限定或偏好；尽量满足时可设置例外数。主科可选第1～4节，音乐可选第8、9节；无需额外规则入口或“学科节次安排方式”字段。

- 例外数表示每班每科每周可不在偏好节次的课时数；设为0且必须满足时，偏好节次成为严格范围。
- 旧“活动课补空”具有条件回退语义，与单纯偏好不同。已有配置应保留旧行为，并标明是历史特殊规则；不能静默转换成固定偏好而改变排课结果。新规则统一使用节次偏好表达。

同一学科如果同时配置互相不同的节次偏好，检查提示职责交叉；老师确认后可以调整节次或停用其中一条。

## 本次增加的配置检查

| 检查 | 判断及反馈 |
| --- | --- |
| 实际重复 | 对比实际配置，忽略编辑文案；教师禁排两个入口统一比对实际课位。提示保留一条，不禁止保存 |
| 完全覆盖 / 部分重叠 | 比对对象、课表类型、单双周、实际课位；说明冗余与独立部分。仅重叠不判断无解 |
| 不同每日上限 | 重叠教师取较严格值；提示合并维护，属于兼容交叉 |
| 允许范围互斥 / 全部禁排 | 同一生效范围没有共同课位，或共同课位全部被禁止；硬规则错误、软要求警告 |
| 学科与任课教师 / 班级交叉 | 根据本年级实际行政班任教关系联结；显示班级、学科、教师名称，不推测走班映射 |
| 班级无空堂与禁排 | 必须有课的前七节被班级/全局禁排；允许末尾空节模式不误判为必须填满 |
| 班主任指定课位与禁排 | 使用实际班主任身份指出冲突；缺少班主任资料提示补全 |
| 下限与可用容量 / 每日上限 | 选定课位最多容量不足以满足周累计下限 |
| 连堂天数 / 连续长度 | 候选日期或连续课位不够，或教师每日上限小于要求的连堂长度 |
| 特殊范围防误报 | 区分停用、软硬、行政/走班、单双周，以及“仅限本人班主任班”的禁排 |

每个报告显示：问题类型、涉及规则、影响范围、具体原因、可选化解方法，以及直接进入关联规则的按钮。不会自动放宽老师的规则。真实休假、会议、班级停课应优先保留；有弹性的偏好可以改为尽量满足。

保存只阻止涉及当前规则的确定硬冲突；老师仍可修复其他规则或保存停用配置。重复和兼容交叉可保存。窄屏使用相同报告，避免只剩一句无法操作的错误提示。

## 三个不同的检查结论

1. **规则结构检查**：对象和参数可以解析；不说明一定能排课。
2. **配置关系检查**：根据已知课位和任教关系发现确定矛盾；没有发现不代表所有约束一定可同时满足。
3. **排课求解与结果检查**：还需验证周课时、学生选课、教师/教室并发资源等整体可行性。

存在配置冲突时，即使服务器结构检查通过，页面也显示“结构可解析，但仍有配置冲突”，不会以绿色“检查通过”掩盖错误。生成失败时，候选放宽建议不能宣称是已证明的唯一冲突原因。

## 后端一致性修复与限制

同一学科的多条硬性允许范围在**同一周**应取交集。此前提取器取并集，会把每条规则本来禁止的课位重新放开；现已修正，并保留空交集。

该旧提取器没有单双周维度，因此先分别求每周交集，再做两周的安全合并；只有一周受限时不错误限制另一周。单独晚课限制不错误用于白天。单双周精确执行仍依赖后续规则检查，不能把该提取器的结果宣称为完整的周期约束求解。

## 仍值得增加的教学能力

这些是明确的下一阶段需求，并未仅通过新增模板名称假装已实现。

| 优先级 | 建议需求 | 原因及验收要点 |
| --- | --- | --- |
| 高 | 每班每科每日次数上限与最少分布天数 | 生成器有默认同科日分布规则，但老师还不能针对数学、美术等分别设置每天次数和每周分布天数。应以实际单双周课时检查“次数上限×可用天数” |
| 高 | 教师最多连续授课节数及必要休息 | 当前连堂是“至少连续”，不能表达“最多连续3节后休息”。应区分午休、白晚课与不同校区移动时间 |
| 高 | 特殊教学资源可用时段和容量 | 实验室、机房、体育场地需要明确资源容量、设备资格和可用时间；应基于资源管理数据，而不是创建名称相近的学科禁排 |
| 中 | 课程先后顺序 / 配套课程间隔 | 如理论课先于实验课、同科两次课最少间隔一天。需要课程级关联以及结果可解释性 |
| 中 | 临时规则有效日期及例外 | 单双周之外的考试周、短期休假等应单独设置有效日期，明确与学期规则谁优先 |

自动教师撞课、班级撞课、课时配额与基础资源检查应由排课及基础资料负责，不要求老师逐条创建重复规则。

## 验证

- 配置检查：19个测试场景，包含真实交叉冲突、兼容重叠、例外数、周期隔离和特殊班主任范围。
- 后端规则与周期回归：92个测试通过，覆盖允许范围交集、空交集、不同周不互相收紧，以及晚课不误限制白天。
- 浏览器流程：验证统一场景入口、方式切换、旧连续性保留/关闭后不自动恢复、跨对象冲突解释、跳转关联规则、错误保存拦截和窄屏布局。
