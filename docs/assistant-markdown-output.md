# 助手输出整理工具

`format_markdown` 在查询完成后接收结构化正式答案，本地生成 Markdown，并直接结束当前回答。无额外模型请求、无数据库访问、无业务写入。简单回答与澄清无需使用工具。

## 输入示例

```json
{
  "summary": "以下是本次查询的结果。",
  "sections": [
    {
      "type": "table",
      "title": "核对结果",
      "columns": ["项目", "状态"],
      "rows": [["示例项目", "待确认"]]
    },
    {
      "type": "steps",
      "title": "下一步",
      "items": ["确认查询范围", "核对结果"]
    }
  ]
}
```

内容块支持：`paragraph`（`text`）、`list`（`items`）、`steps`（`items`）、`table`（`columns`、`rows`）。`title` 可省略；`sections` 可为空。表格单元格使用字符串，包括数字。

## 约束

- 只包含正式结论、已查询事实、标明假设的建议或待确认项；工具不会核验事实真实性。
- 不接受额外字段与 `think` / `analysis` 标记；HTML 转义。未标记的自然语言分析仍需由模型遵守提示词，不构成语义安全保证。
- 最多 8 个内容块，列表最多 20 项，表格最多 5 列、30 行，支持科目与三方案并列表。行宽必须与表头相同。
- 数字课时表核对分项、合计和标题；最终方案逐科与程序验算结果对照。文本块不得夹带压平的 Markdown 表格。
- 最终出口仅恢复可明确识别的标题和表格行边界，不改科目与数字；有歧义的行交由模型在原预算内纠正。
- 参数最多 30000 字符，输出最多 12000 字符；拒绝过长内容，不截断答案。
- 单独调用，不与查询或草稿工具同批调用。混合调用时拒绝整理，避免查询尚未完成便输出答案。
- 非法参数返回 `INVALID_ARGUMENT`，允许模型在现有轮次上限内纠正。
- 保留原有英文分析泄露检查与中途方向调整处理。
- 仅向允许工具的任务开放；快速回答任务不添加工具。计划模式可使用，但不会因此开放写入权限。

实现：`backend/app/ai/tools/markdown.py`。执行入口：`gateway/tool.py`。终结回复：`graph/loop.py`。输出格式变化不会修改课时、任课关系或课表。
