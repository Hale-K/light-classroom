# 助手业务查询工具

本轮补齐保存数据的查询与基础校验。没有数据库迁移，不需要安装新依赖；不会修改选科、行政班、任课关系、课时或课表。工具定义、服务端派发、查询模式和计划模式已接通。

## 能力清单

| 工具 | 证据 | 查询示例 |
| --- | --- | --- |
| `lookup_school_context` | 学校当前课表模式、默认高考模式、学年学期和可用课程类型 | 我校现在是什么课表模式？ |
| `lookup_student_choices` | 学生选科状态、科目人数、行政班归属、教学班入班、重复同科入班 | 高一物理有多少人选，还多少人没入班？ |
| `lookup_teaching_assignments` | 行政课与走班固定任课、课时方案、实际已排节数、教师不一致、配置工作量 | 高一甲老师带哪些班，课时多少？ |
| `lookup_timetable` | 已保存行政课和走班课，支持个人、教师、班级、科目和时段筛选 | 高一学生甲周一的课表是什么？ |
| `lookup_schedule_conflicts` | 教师、学生、班级和教室同一时段碰撞 | 高一行政课和走班课有没有冲突？ |

原有教师查询、准备度、规则、科目容量、剩余课位、课位角色容量、生成状态、求解日志、教学班汇总和操作手册保留。

## 参数和范围

- 学年学期明确传入，或继承当前页，缺省时读取学校当前设置；学期只接受 `1`、`2`。
- 年级用 `grade_id` 或名称 `grade` 指定，也可由明确的行政班推导。年级缺失或有歧义返回 `MISSING_SCOPE`，不会默认为全校。
- 行政班用 `class_id` 或完整名称 `class_name`；教师用 `teacher_id` 或完整姓名 `teacher`；学生用 `student_id` 或姓名/学号 `student`。名字不能唯一匹配时要求澄清。
- 显式指定年级或班级时覆盖页面选择，防止查错范围；不同显式选择互相矛盾时拒绝查询。
- `subject` 为精确科目名。课表与冲突另支持 `weekday`（1–7）、`period`（1–30）。选科和任课不接受时段筛选。
- 查询输出包含实际 `scope`、`total`、`items`、`offset`、`limit`、`has_more`、`next_offset`。默认每页 50 条，最多 100 条；汇总基于完整匹配范围，不能只把当前页当全部结果。
- 返回 `EMPTY_RESULT` 表示没有匹配保存记录；`INVALID_ARGUMENT`、`MISSING_SCOPE`、`FORBIDDEN` 是明确错误，不能以空结果推断业务完成。

## 身份和数据隔离

所有数据查询按租户隔离。共享科目允许 `tenant_id` 为空，教师和学生不跨校查询。服务端工具网关在执行新增工具前查询当前账号身份，学校级查询只开放给教务主任或本校有 `academic_director` 岗位的在职、未冻结教师；规则写权限和页面上下文不能代替身份校验。普通教师/班主任的个人与本班范围授权尚未接入这些学校级工具。

## 校验口径

- 回答前服务端读取学校环境并注入模型上下文；环境读取失败时明确未核实。当前设置不能用来证明历史学期的模式。
- `administrative`（行政班）与 `walk_class`（选科走班）是两种课表模式；`3+1+2` 是选科模式，不能据此断定课表模式。
- 走班课表包含 `administrative` 行政公共课和 `walk` 选科教学班课；`lesson_type=combined` 合并查询。行政班模式不会读取遗留走班记录，显式要求走班类型返回 `MODE_MISMATCH`。
- 数字分配与方案比较默认用表格，标明单位、查询依据与建议。明确可加的科目课时表会核对分项和合计，不一致时先要求模型纠正；持续错误则不交付该答案。带单双周限定的数字不会擅自换算。
- 分页证据保留完整 JSON 供模型读取，不按普通文本的4000字符上限切断，以免丢失范围、汇总和下一页信息。

- 学生年级人数来自学年年级快照、学期行政班归属和已保存教学班成员；缺少这些关联的学生无法统计，返回 `population_basis`。不拿当前学生班级补历史数据。
- 未入行政班、教学班无成员、无选科和选科草稿分别展示。科目人数包含各状态并附 `choice_status_counts`；不能把草稿视为已确认选科。未入班不代表生成失败。
- 行政班课时方案按每周、单周和双周分别返回，晚课另列；任课记录中的课时与课时方案分开。教师汇总的已排节数按课表实际教师统计，配置工作量按固定任课统计；仅代表当前查询范围。
- 个人课表只合并保存的行政课和走班课，不把页面按规则临时补出的自习表述为已保存课程。
- 冲突按单周和双周分别检查，单周与双周错开的课程不碰撞。筛选科目、教师、班级或时段只确定待检查课程，竞争课程仍来自本校该学期全部年级。
- 冲突条数是「资源 × 时段 × 周次」记录数，教师、学生和教室可能指向同一组课；不能把总数解读为不同课程对数。
- 教室只有保存的名称，因此同名匹配是候选冲突，返回 `candidate_only`；未核实校区、房间别名和未填教室。缺名单的学生冲突不能完整检查。
- 缺失数据明细最多 100 项，同时返回总数及截断标志；教师汇总超过 100 人也明确标记截断，可以按教师继续查询。
- 未核验全部规则、资源容量、连堂、跨校区移动、晚课边界或求解可行性；`full_rule_validation` 恒为 false。未发现基础碰撞不等于课表全面通过。

## 验证

`backend/tests/test_assistant_school_queries.py` 使用真实 SQLite 查询和只允许 SELECT 的适配器，验证租户、学期、历史归属、名字解析、分页、单双周、跨行政/走班/年级碰撞、配置与实际教师区分以及学校级查询权限。现有助手回归测试覆盖工具网关、路由、提示词、计划模式、工具循环和确认写入边界。

开发环境运行测试时将工作目录设为 `backend`，让项目配置正确加载。可选 PostgreSQL 测试需要显式启用对应环境变量。

2026-10-08 相关助手、工具循环和模式隔离回归：212项通过，2项跳过。全量后端测试曾长时间停滞并中止，未宣称全量通过。真实浏览器验收使用当前行政班环境，不切换学校设置；走班和两种课程类型的查询隔离由SQLite测试覆盖。
