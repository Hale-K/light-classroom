# 配置流程排查与多机构适配

日期：2026-10-09。范围：学校设置、届别/年级、组织与账号、空间资源、学生、分班、选科、课时、任教、规则、排课及返回原任务。

实施状态：本轮按现有高中学校流程收敛优化，没有扩展高校、教培、小学等机构类型。已完成年级与校区解耦、年级后补校区、组织树防循环、年级部名称与人数统计解耦、组织表单内补建年级、资源表单去除“必须经过年级中心”的提示、当前期次一致性以及13步准备清单。学校业务数据未被修改。

结论：当前产品以普通高中为核心，缺失前置步骤、名称判断、跨页面补数据和无法补关联共同造成操作阻塞。仅调整菜单顺序不能覆盖这些问题。组织中心并非当前主入口的必备条件，但旧页面、帮助文档及部分文案仍要求它。

## 实际流程与依赖

| 阶段 | 真正依赖 | 现有提示/入口 | 判断 |
|---|---|---|---|
| 学年学期、届别 | 学校管理员；当前高中届别配置 | 系统设置基础配置和届次管理 | 当前届别自动推导只覆盖高中三年 |
| 年级基础数据 | 后端仅要求名称与1—3层级；校区允许为空 | 前端无校区禁用新增，校区必填 | 页面引入额外强依赖；已有空校区记录无编辑入口 |
| 组织年级部 | 对应年级；资源业务额外需要届别 | 人员账号新建组织；类型与对应年级必填 | 上级可选，年级中心不必备；届别可不填，后续资源页面却排除它 |
| 学科组 | 对应科目 | 科目为空可跳转科目管理 | 必要关联，但离开表单没有返回状态 |
| 人员账号 | 基本登录信息；教师类型要求职级 | 所属组织可空；支持未分配组织列表 | 账号不依赖年级；任职和部分教师候选后续依赖年级部 |
| 空间 | 校区→楼宇→场室 | 逐级新增；缺上级时按钮禁用 | 对线下空间合理，但不能成为所有机构教学工作的通用前置 |
| 届别资源分配 | 有届别的年级部、校区、场室、学年学期 | 缺年级部有去设置；校区空仅下拉；预览后执行 | 隐藏的组织前置，且分配默认同届复用与行政建班独占要求不一致 |
| 行政班规划 | 前端必须选年级部；已分配独占教室 | 无资源有说明；建班弹窗缺年级部无直接补充入口 | 班级建立被绑定到资源分配，无法充分支持先建班、后排教室 |
| 学生与分班 | 学生归属、班级、当前学期；自动分班筛选有教室的班 | 学生模拟缺届别有警告；自动分班需预览确认 | 部分年级筛选依赖名称和树顶层；资源与名单相互影响，未列成完整引导 |
| 班主任与任教 | 可用教师、角色、年级任职、科目/班级 | 部分候选仅取年级部任职；无唯一学科组会提示 | 添加教师账号不等于已准备好任教，缺项缺少统一补充动作 |
| 课位与课时 | 年级、班级、教学时间安排 | 有保存和缺年级提示 | 课时准备度按每班存在正课时计数，不能证明每科完整 |
| 行政排课 | 当前课位、任教与生成范围；页面要求选择综合规则组 | 没有组时要求先建综合规则 | 与“普通排课无需先创建规则”的引导存在范围选择流程冲突 |
| 走班排课 | 学生已确认选科、教学班和共享空间等 | 有选科提示、预览及替换确认 | 属于专门能力，不应作为小学、初中或所有高校的固定流程 |
| 补数据后返回 | 原任务、表单、年级、学年学期 | 多处仅navigate到目标页 | 没有统一草稿保存、返回任务、补完回读机制 |

## 已确认问题与优先级

P0表示可能造成结构或业务证据错误；P1表示主要流程阻塞；P2表示文案、引导和可用性。

| 编号 | 级别 | 问题与触发 | 影响 | 证据/建议 |
|---|---|---|---|---|
| F01 | P0 | 编辑上级只排除自己，后端没有阻止移动到自己的后代 | 可创建组织环，相关节点随后被当前树过滤，表现为组织消失 | 内存接口探针复现。修改接口和选项都应排除后代，保留原结构并给明确错误 |
| F02 | P0 | 资源人数按年级部名称中的高一/高二/高三推断层级 | 改名后即使grade_id正确，也返回人数未关联，无法完成可靠容量判断 | 内存探针：新生教学部绑定高一且有1名学生，返回null。应按明确关联与当前成员快照计算 |
| F03 | P1 | 年级前端强制校区，后端允许空；列表没有编辑操作，API未提供年级更新接口 | 已存在空校区年级只能看到未关联，不能在该页面补充；不能直接推出“允许稍后关联”已经可用 | settings/GradeManagementPanel.tsx；api/v1/org.py。补更新入口、范围验证和待办，再放宽前置 |
| F04 | P1 | 年级部允许不填对应届；资源页面只收录有届别的节点 | 建好组织后仍看不到选项，被误认为没建年级部 | 接口探针与allocation-rule-drawer.tsx。区分不存在与未配置届别，指出具体节点并可补充 |
| F05 | P1 | 新手引导只有10项，省略年级、组织、届别关联和学生准备 | 用户照建议顺序做仍会卡在资源分配 | evaluate_steps；页面截图。按当前能力列出缺失依赖，保留可跳过项 |
| F06 | P1 | 分配规则默认shared；行政班候选仅exclusive | 用户按默认值完成资源分配后可能仍无可用建班教室 | 表单初始值与planCandidateRooms。按实际用途建议选择，并在建班时明确为何被排除 |
| F07 | P1 | 资源表单显示当前学年，normalizedValues却优先用目标年级部academic_year | 显示期次与最终传参可能不同，旧组织节点可能导致分配到旧学年 | 代码路径确认；未提交数据。必须统一显示与提交范围，并提示不匹配 |
| F08 | P1 | 行政生成入口无综合规则组就返回；引导称规则可选 | 用户无法按“规则可跳过”的提示完成页面生成 | openGenerationRulePreview与evaluate_steps。基础范围选择与可选额外约束分开 |
| F09 | P1 | 学生档案部分年级筛选仅看组织树顶层，并按名称判断 | 组织改为中心/部门嵌套后筛选结果可能与直接挂学校时不同 | students/index.tsx:236附近。递归遍历，统一按grade_id及当前期次过滤 |
| F10 | P1 | 班主任候选依赖年级任职；部分任教操作需要唯一学科组 | “已经添加教师”之后仍可能没有可用候选 | classes/index.tsx与scheduling/index.tsx。给出缺年级任职、缺科目或角色的逐人说明 |
| F11 | P2 | 当前组织页面不强制年级中心，帮助文档及资源占位文案仍要求中心 | 让用户误以为组织只能用预设结构 | 当前/staff路由、Tutorial.tsx、资源表单及旧organization页面。统一主流程与文案 |
| F12 | P2 | 多处去设置关闭当前表单，目标设置默认落在基础配置 | 补完仍需自行找年级页、重开表单和重新输入 | SelectEmptyGuide、资源表单、SchoolSettingsForm。使用明确目标与草稿返回，避免只做裸跳转 |
| F13 | P2 | 没有校区但已有年级时，新建按钮禁用，空表说明不显示 | 用户看到现有年级和禁用按钮，却看不到禁用原因 | 真实合成学校页面截图。始终显示原因及创建校区动作 |
| F14 | P2 | 课时与任教完成度按有记录的班数判断，已生成按有课表项判断 | 部分数据可显示步骤已完成；不能作为完整可排保证 | load_onboarding_status。区分建立记录、业务完整、可执行与已完成，不能只使用同一个done |

组织创建、更新仅允许校长管理员；教务人员遇到此依赖需要可执行的联系管理员路径。此轮没有改变角色权限，也没有假定每位老师都应该获得组织管理权。

## 跨机构的统一设计

新增独立的机构类型与教学能力配置；不要复用现有Tenant.type（它已有租户类型含义）。机构类型用于初始模板，实际能力决定菜单、字段、准备流程和校验。默认模板不能成为无法调整的制度。

| 模板 | 常见组织与学生范围 | 时间与课程 | 默认启用能力 | 应可关闭/隐藏 |
|---|---|---|---|---|
| 小学 | 校区、年级、行政班、教研组；年级范围按学制配置 | 固定班课表、课程与周课时 | 班级、班主任、教师、课表、考勤 | 高考模式、选科走班、届别独占资源流程 |
| 初中 | 年级、班级、学科组；学制可配置 | 固定班课表，可有分层/选修教学 | 行政教学及按需选修 | 高考政策、固定高一年级词汇 |
| 高中 | 年级、行政班、选科教学班 | 行政课与选科课并存 | 当前高中能力；按学校选择走班 | 不应强制每校都走班或固定某学期切换 |
| 高校 | 校区、院系、专业、入学批次、行政班与课程教学班 | 学期、教学周、学分、课程开设、学生选课 | 课程教学班、选课、教师/学生课表、场室共享 | 高考选择规则、行政班独占教室、三年学制 |
| 教培 | 校区/教学点、课程班、一对一、学员 | 按日期或周期开课，可跨月跨学期，时长可不同 | 课程班、报名、老师可用时间、预约/调补课、出勤 | 强制年级、届次、两学期、完整校园空间层级 |

高校和教培在现有代码基础上需要新增领域能力，不能通过改文案或换机构标签宣称已适配。收费、课包与课时消耗属于可单独规划的经营能力，不强塞到第一阶段排课改造里。

核心概念应明确分离：组织归属（院系/部门/年级部）、学习归属（年级/专业/入学批次/行政班）、授课编组（课程教学班/培训班/一对一）、课程开设（某一周期中由教师提供的课程）、实际授课事件（日期时间、教师、学员范围、地点）。显示名称不应承担关联关系或算法输入。

教学时间支持学校学期、教学周/单双周与实际日期时间；教培一次课和高校某教学周课表不能都塞进固定行政班weekday/period字段。可沿用当前高中课表，以新增教学事件与课程开设模型扩展，保持历史结果与来源关系。

校区/空间在需要场地的任务中校验；线上课使用明确线上场所能力，不能要求用户伪造一个校区或教室。一个校区可建议预选并确认，多校区不得根据名称猜测。多人操作时，缺项提示和完成状态必须来自实时数据，而非个人忽略提醒后全校消失。

## 可实施顺序

1. 先修当前配置完整性：组织环、名称推断、年级可编辑、届别缺项、shared/exclusive用途与期次一致；这些属于所有机构共有的基础。
2. 建立能力驱动的准备清单：每项有适用条件、缺失对象、影响任务、权限要求、补充动作和回读验证；创建可保存草稿，执行前做必要校验。
3. 支持就地补充与返回原任务：保存年级/组织/资源表单草稿及当前业务范围，补完不自动保存原业务，先回读并展示再继续。
4. 去掉高中专用层级/学制/术语硬编码，提供小学、初中、高中模板，并保留现有学校的高中默认配置和历史数据。
5. 新增通用课程开设、学生课程关系与授课事件，试点教培预约课程和高校课程教学班，再补学分/选课限制或课包等各自业务。
6. Agent继续只有普通查询、复杂规划两类语义；从服务端取得机构类型、实际能力、学期/时间和角色范围，使用对应查询和校验工具。不根据老师自称、页面标题或年级名称猜环境。

## 取证与限制

代码查询优先使用知识图谱；图谱对部分前端返回空或片段过期时直接核对实际文件和当前路由。相关基线测试38项通过（2.21秒），这不证明上述缺失场景已通过；新增探针实际复现三个问题。

- [复现脚本](../backend/scripts/configuration_flow_probe.py)：只建立内存SQLite，用同步SQL Session适配协程接口，实际调用现有创建/修改接口函数；不经过HTTP、中间件或生产数据库。
- [探针结果](configuration-flow-probes.json)：后代移动可提交且树节点消失、无届别年级部可创建、自定义名称导致关联人数为null。
- [年级页面截图](screenshots/flow-grade-unlinked.jpg)：真实合成学校已有未关联校区年级，没有编辑操作，新建按钮禁用。
- [年级部表单截图](screenshots/flow-grade-group-form.jpg)：上级可选、对应年级必填、对应届非必填。
- [资源分配截图](screenshots/flow-resource-allocation.jpg)：界面仍要求年级中心文案，且默认同届复用。
- [新手引导截图](screenshots/flow-onboarding.jpg)：遗漏年级/年级部/届别、学生步骤。

页面只做读取、打开表单及取消；未创建账号、改变权限、移动或归档真实组织、分配资源、分班或启动实际排课。高校与教培流程为基于现有代码的设计方案，尚未实施或页面验收。
