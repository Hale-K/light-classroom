# 科目页面操作助手（第一版）

现有助手先把带有操作请求表达的消息交给配置的大模型做意图识别，判断是新增科目还是普通对话；识别不依赖用户必须说出「科目」等固定目标词。识别为新增科目后，再提取名称、课程类型和晚自习资格，询问缺少的信息；字段齐全后自动打开科目管理页，通过 Page Agent 点击新增、填写、保存，再查询科目列表核实结果。已在科目管理页时直接执行。

也可以一次提供「帮我新增科目叫心理，类型为活动课，允许晚自习」。当前仅支持一次创建一个科目。名称必填且不超过 20 字；课程类型和晚自习资格必须由用户明确提供，禁止将表单默认值当成用户输入。未提供的字段为 null，与明确不允许的 false 区分。同名科目在数据完整后跳过。待补充的草稿按学校和账号保存在当前浏览器会话中，刷新后可以继续补充；新对话或输入「取消」会清除草稿。执行中的任务刷新后不会自动重放。草稿使用新版存储键，避免沿用旧版自动填入的默认值。

## 运行与预览

前端执行 `pnpm install`，按原流程启动前后端。实际操作需要已登录，身份为校长管理员或教导主任，并在服务商管理中启用支持 OpenAI 兼容 tool calling 的对话模型。入口复用项目的教务管理身份校验，无需额外的排课配置权限。API key 只保留在后端，不传给浏览器。

开发环境打开 `http://127.0.0.1:5176/tests/page-subject-agent.html` 可体验隔离演示。它使用真实 AssistantDock、科目表单和 Page Agent，但模型响应与科目 API 都是测试数据，不访问学校数据库、不产生模型费用。需要明确提供名称、课程类型和晚自习资格；模型失败、误报成功和等待模型场景也可切换。测试入口不进入生产构建。

## 执行边界

- 后端先检查学校、权限、名称、课程类型和重名，再签发绑定账号、学校与表单数据的 15 分钟任务令牌。
- 页面加载完成后才启动 Page Agent；只索引新增按钮、科目表单和课程类型选项。脚本执行工具关闭。
- 保存时再次核对表单与已校验数据完全一致，不允许借任务编辑现有科目。
- 提供停止按钮；已提交的 HTTP 保存请求可能继续完成，因此停止后需要核对列表。
- 最终成功取决于科目列表查询结果，不采用模型自称的成功。页面操作最多 16 步、约 2 分钟。
- 页面跳转等待最多 15 秒。已有编辑窗口时停止，不覆盖正在编辑的表单。

## 验证

```powershell
cd backend

cd ../frontend-react
node --experimental-strip-types --test src/assistant/subjectTask.test.ts

```

浏览器验证使用隔离演示，覆盖缺数据追问、补充后跳转创建、当前页直接创建、重名跳过、模型失败、误报成功核验与停止操作。真实模型的操作效果需在学校配置的模型上继续验证。

2026-10-05 已使用真实登录账号和 GLM-5.3-Flash 完成两轮输入测试：从排课规则页发起新增「人工智能基础」，追问缺少的课程类型和晚自习资格；补充活动课、不允许晚自习后，真实 Page Agent 自动跳转、填写和保存，页面列表与保存核验均确认正确。校验接口约 4～6 毫秒，7 次页面操作模型请求各约 6～9 秒，完整执行约一分钟。GLM-5.3 系列页面操作使用 `reasoning_effort=low`，保持模型可用且减少简单操作的推理等待。开发启动脚本启用后端自动重载，避免旧进程继续执行旧代码。
