# 轻课堂知识库 RAG 实施计划

## 目标

为教务助手增加按学校隔离的知识库能力，支持文档上传、解析、分块、向量化、语义检索、引用回答和权限控制，并接入现有 AssistantGateway。

## 架构

```text
文档上传
  → 文档解析器
  → 文档分块器
  → BGE Embedding
  → PostgreSQL + pgvector

用户提问
  → 意图路由
  → 判断是否需要检索
  → pgvector 检索（tenant + 权限过滤）
  → 可选 reranker
  → Ollama qwen3:8b
  → 带来源引用的回答
```

## 分阶段任务

### 阶段一：数据基础

- 新增 `knowledge_base`、`knowledge_document`、`knowledge_chunk` 三张表。
- 所有记录包含 `tenant_id`、创建人、状态和更新时间。
- `knowledge_chunk.embedding` 使用 `VECTOR(768)`，建立 cosine HNSW 索引。
- 增加 Alembic migration 和回滚脚本。

验收：迁移可重复执行；不同学校无法查询彼此的数据。

### 阶段二：文档入库

- 支持 Markdown、TXT、PDF、DOCX。
- 解析原文并按标题、段落和长度切分。
- 记录页码、标题、文件名等来源信息。
- 后台任务执行 embedding，避免阻塞 HTTP 请求。
- 失败任务可重试，重复上传使用文件哈希去重。

验收：上传后能看到处理进度，失败能看到原因，成功后 chunk 数量和来源可追溯。

### 阶段三：检索服务

- 新增稳定的 `KnowledgeSearchService` 接口。
- 使用 BGE 生成问题向量并查询 pgvector。
- 强制加入 `tenant_id` 和文档权限过滤。
- 支持 top-k、最低相似度和最大上下文长度配置。
- 预留 `bge-reranker-base` 重排接口，但第一版可关闭。

验收：同一问题能返回相关片段、相似度和来源；无结果时返回空结果而不是编造内容。

### 阶段四：助手接入

- AssistantGateway 在需要知识时调用 `KnowledgeSearchService`。
- 将检索片段作为受标记的上下文传给模型。
- 回答中返回文档、章节或页码引用。
- 记录检索请求、命中片段、模型是否采用引用到 `AiRun.events`。
- 保留无检索问题的普通对话路径。

验收：普通问候不触发检索；校务问题能引用知识库；模型服务不可用时仍能返回检索结果或说明。

### 阶段五：前端知识库菜单

- 增加“知识库”菜单和权限码。
- 知识库列表、新建、编辑、启停和删除。
- 文档上传、处理状态、失败重试和来源查看。
- 检索测试面板，显示命中的文档片段。

验收：菜单按角色显示；教师只能访问被授权的知识库；管理员可管理本校知识库。

## 依赖策略

- PostgreSQL + pgvector：向量存储和检索。
- BGE：当前沿用 backend 本地 `sentence-transformers`；后续可拆为独立 embedding 服务。
- Ollama：提供 `qwen3:8b` 对话模型，不承担向量数据库职责。
- Redis：承载文档解析和 embedding 后台任务状态。

## 关键安全约束

- 所有查询必须带 `tenant_id`，不能由前端传入并直接信任。
- 文档内容作为不可信数据处理，禁止其覆盖系统指令或触发工具调用。
- 知识库写入、删除和批量重建必须人工确认。
- 限制文件大小、页数、chunk 数量和单次 embedding 预算。
- 删除知识库采用软删除和异步清理，保留审计事件。

## 风险

| 风险 | 应对 |
| --- | --- |
| BGE 首次加载慢、占用内存 | 后台预热或独立 embedding 服务 |
| 文档内容污染模型上下文 | 明确上下文边界、来源引用和提示注入防护 |
| 多学校数据串读 | 服务层强制租户过滤并增加越权测试 |
| 大文件消耗过多 token | 分块、top-k、上下文预算和截断策略 |
| 解析质量不稳定 | 保存原文、来源定位和失败重试 |
